# Дорожная карта AutoML и критерии готовности к запуску

## Цель документа
Определить этапы внедрения AutoML и формальные критерии, по которым можно оценить готовность платформы к стабильной работе в production.

## Этап 0. Инициация и границы проекта
**Срок:** 1-2 недели  
**Результат:** утвержденный scope внедрения.

### Что сделать
- Определить 1-2 приоритетные задачи (например: классификация изображений и табличный скоринг).
- Зафиксировать бизнес-метрики и технические KPI.
- Определить бюджет вычислений и целевые SLA/SLO.

### Критерии готовности (Gate 0)
- [ ] Есть документированный scope задач и ограничений.
- [ ] Для каждой задачи определены KPI (качество, latency, стоимость).
- [ ] Назначены ответственные роли (DS, MLOps, DE, Product/Domain).

---

## Этап 1. Данные и контроль качества
**Срок:** 2-4 недели  
**Результат:** воспроизводимый датасет и валидационные процедуры.

### Что сделать
- Ввести versioning данных и схем (Data Contract).
- Собрать quality checks: пропуски, дубликаты, дисбаланс, утечки.
- Утвердить правила разметки и контроль согласованности.
- Сделать стабильный split train/val/test.

### Критерии готовности (Gate 1)
- [ ] Данные версионируются и доступны для rollback.
- [ ] Data quality checks автоматизированы и запускаются регулярно.
- [ ] Есть golden set для контроля качества модели.
- [ ] Split воспроизводим и исключает пересечения/утечки.

---

## Этап 2. Базовая MLOps-инфраструктура
**Срок:** 2-3 недели  
**Результат:** готовая платформа для запуска экспериментов AutoML.

### Что сделать
- Подключить experiment tracking (метрики, параметры, артефакты).
- Включить model registry с версиями и стадиями (Staging/Prod).
- Настроить пайплайн оркестрации и запуск задач на GPU/CPU.
- Внедрить CI-проверки для ML-конфигов и скриптов.

### Критерии готовности (Gate 2)
- [ ] Каждый эксперимент имеет traceability (код + данные + параметры).
- [ ] Модель можно зарегистрировать и воспроизвести из реестра.
- [ ] Есть квоты/лимиты на ресурсы и контроль очередей.
- [ ] Базовые CI-проверки проходят стабильно.

---

## Этап 3. AutoML-ядро (поиск и отбор)
**Срок:** 3-6 недель  
**Результат:** рабочий контур автоматизированного поиска моделей.

### Что сделать
- Определить search space по каждому типу задач.
- Настроить HPO (TPE/Bayesian/ASHA) с бюджетом trial-ов.
- Реализовать автопредобработку и feature engineering-пайплайны.
- Добавить правила выбора лучшей модели (multi-metric ranking).

### Критерии готовности (Gate 3)
- [ ] По каждой задаче есть валидированный search space.
- [ ] Запуски AutoML ограничены по времени и ресурсам.
- [ ] Результаты сравнимы с baseline и превосходят его по KPI.
- [ ] Формализованы причины отклонения неуспешных запусков.

---

## Этап 4. Валидация надежности
**Срок:** 2-4 недели  
**Результат:** подтверждение устойчивости моделей.

### Что сделать
- Провести robustness-тесты (шум, пропуски, сдвиг распределений).
- Выполнить error analysis по сегментам пользователей/данных.
- Проверить калибровку вероятностей (если нужна).
- Зафиксировать risk register и ограничения использования модели.

### Критерии готовности (Gate 4)
- [ ] Модель устойчива на ключевых стресс-сценариях.
- [ ] Известны слабые сегменты и план их улучшения.
- [ ] Документированы границы применимости модели.
- [ ] Подписан go/no-go протокол к продакшену.

---

## Этап 5. Вывод в production
**Срок:** 1-3 недели  
**Результат:** безопасный запуск с наблюдаемостью.

### Что сделать
- Внедрить canary/A-B rollout.
- Настроить online-мониторинг (drift, качество, latency, ошибки).
- Определить retraining triggers и расписание переобучения.
- Подготовить rollback-процедуру и on-call инструкции.

### Критерии готовности (Gate 5)
- [ ] Есть автоматические алерты по качеству и деградации.
- [ ] Есть регламент retraining и ручного override.
- [ ] Rollback проверен на staging.
- [ ] SLA/SLO выполняются на пилотном трафике.

---

## Сводный индекс готовности AutoML (0-100)
Для быстрой оценки можно использовать weighted score:

- Данные и качество — **25%**
- Инфраструктура и воспроизводимость — **20%**
- Качество AutoML-поиска — **20%**
- Надежность/робастность — **15%**
- Продакшен-мониторинг — **20%**

**Интерпретация:**
- **0-49**: не готово к production.
- **50-74**: ограниченный pilot/staging.
- **75-89**: условно готово (под контролем рисков).
- **90-100**: готово к масштабированию.

## Мини-чеклист перед реальным запуском
- [ ] Метрики качества и бизнес-эффекта достигли целевых порогов.
- [ ] Data/Model drift мониторится и алертится.
- [ ] Имеется подписанный runbook (incident + rollback).
- [ ] Прозрачно оценена стоимость обучения и инференса.
- [ ] Назначены владельцы процесса переобучения.
